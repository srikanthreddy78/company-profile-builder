# Security notes

This tool fetches arbitrary public web pages, feeds them to an LLM, and writes files. The
controls below are implemented in code. The last column names the regression tests that
exercise a control; "no dedicated test" means the control exists in code but is not asserted
by the suite.

| Threat | Control | Where | Tests |
|---|---|---|---|
| **SSRF** via the start URL, discovered links, or redirects | `http(s)` only; no embedded credentials; default ports only; URL length cap; the hostname is resolved and **every** A/AAAA answer must be publicly routable (no loopback, RFC1918, link-local incl. cloud metadata `169.254.169.254`, CGNAT `100.64/10`, multicast, reserved, unspecified, IPv6 `::1`/`fc00::/7`/`fe80::/10`, IPv4-mapped, 6to4/Teredo). Numeric hosts in decimal/hex/octal forms are rejected. Malformed or hostile URLs raise `URLGuardError` (never a crash). The **final URL after redirects** (Firecrawl's engine-reported `metadata.url`) is re-checked and must stay on the same registrable domain with no https→http downgrade; well-known multi-tenant hosts (`*.github.io`, `*.vercel.app`, …) are treated as separate sites and IP hosts compare exactly. `robots.txt` is fetched through the same guard with a timeout. | `web/url_guard.py`, `agent/tools.py::process_page`, `web/robots.py` | `test_url_guard.py` (rejected forms, DNS rebinding, normalization, same-site); `test_security_review.py` (engine final URL, off-site redirect, hostile links, numeric hosts, multi-tenant domains); `test_review_round3.py::test_private_ip_redirect_empty_and_truncated_pages` (`REDIRECT_REJECTED` for a private-IP final URL); `test_cli.py::test_start_rejects_private_url` |
| **Prompt injection** from scraped content | The agent has no action tools beyond the run's own SQLite store (read-only virtual filesystem, no shell). Deep Agents' default general-purpose subagent and `task` tool are disabled, so every tool call passes through our middleware stack; the builder fails fast if `task`/`execute` ever appear. Web-derived tool output is wrapped in "untrusted content" delimiters by middleware and any `<<<`/`>>>` inside page text is neutralized so the region cannot be closed early; the system prompt states page text is data. Instruction-like phrases are detected and logged as `INJECTION_SUSPECTED` without being acted on. | `agent/builder.py::disable_default_subagent`, `agent/middleware.py::UntrustedContentMiddleware`, `security.py::detect_injection`, `agent/prompts.py` | `test_happy_path.py::test_untrusted_content_is_framed_and_injection_flagged`; `test_security_review.py::test_agent_exposes_only_our_tools`; `test_logging_and_security.py::test_excerpt_verification_and_injection` |
| **Fabricated facts, URLs or quotations** | Every website evidence row must name a page fetched in this run, quote a verbatim (whitespace/markdown-normalized) substring of its cached text of 25–1000 characters (`MIN_EXCERPT_CHARS`, `MAX_EVIDENCE_EXCERPT_CHARS`), and share at least one content word with the value it supports; list values are verified per item, so one excerpt grounds only the items it mentions. Rejections are returned to the model with a `reason_code` and recorded as `EVIDENCE_REJECTED`. Interview evidence must reference an answered question that covered that field, and the value must reflect the answer. When a value changes, the evidence attached to that path (and its children) is marked stale. User answers take precedence over later drafts and cannot be overridden by website evidence. Field paths are validated against the contract allowlist and values are re-validated with Pydantic after every update. At export, populated fields without accepted evidence and values under unresolved conflicts are omitted (`UNGROUNDED_OMITTED`, `CONFLICT_UNRESOLVED_OMITTED`); after export `grounding.ungrounded` in `evidence.json` is therefore empty by construction and the omitted paths are listed in the warning. | `agent/tools.py::_verify_website_evidence`, `schema.py::parse_field_path`, `agent/tools.py::finalize`, `workflow/gaps.py::grounding_report` | `test_security_review.py::test_evidence_must_mention_value_and_interview_evidence_is_scoped`; `test_review_round2.py::test_ungrounded_claims_are_omitted_from_export`, `::test_user_answer_survives_later_draft_and_blocks_website_override`, `::test_reexport_does_not_delete_more_items`; `test_review_round3.py::test_G1_list_excerpt_grounds_only_the_items_it_mentions`, `::test_evidence_rejection_codes_for_source_and_length`, `::test_F5b_failed_output_write_rolls_the_store_back`; `test_logging_and_security.py::test_excerpt_matching_ignores_markdown_syntax` |
| **Secret leakage** | Keys are `SecretStr` loaded from env/`.env` only (never CLI args). A redaction filter masks the loaded keys and `sk-…`/`fc-…`/`lsv2_…`/`Bearer …` patterns in every log record, including exception text; the same redactor runs on warnings stored in the run database and on error text printed to the console. Typer tracebacks never show local variables (`pretty_exceptions_show_locals=False`). `.env` is git-ignored; `doctor`/`status` show presence only. | `config.py`, `logging_setup.py::RedactSecretsFilter`, `logging_setup.py::redact_text`, `cli.py` | `test_logging_and_security.py::test_events_carry_context_and_redact_secrets`; `test_review_round2.py::test_transient_error_text_is_redacted_before_storage`; `test_cli.py::test_doctor_without_keys`. Traceback locals: no dedicated test. |
| **Path traversal** via `--run-id` / `--runs-dir` | Run ids must match `^pb-\d{8}-[a-z0-9]{6}$`; every artifact path is resolved and asserted to stay inside the runs directory; cache file names are SHA-1 of the URL. | `security.py::validate_run_id`, `security.py::safe_child` | `test_logging_and_security.py::test_run_id_and_path_safety`; `test_security_review.py::test_run_id_rejects_trailing_newline_and_injection_patterns` |
| **Half-written outputs / permissions** | `company_brain.json`, `evidence.json`, `report.md` are validated first and published all-or-nothing (each staged to a temp file, renamed in sequence, previous versions restored on any failure) inside the finalize transaction, so a failed write rolls the store back. The CLI sets `umask 077`; run directories are `0700`; databases, logs, caches, `evidence.json` and `report.md` are `0600` (they contain interview answers); only `company_brain.json` is `0644`. A fatal run never writes a profile. | `security.py::atomic_write_text`, `agent/tools.py::finalize`, `workflow/export.py`, `cli.py` | `test_logging_and_security.py::test_atomic_write_and_terminal_escape`; `test_invalid_model_output.py::test_invalid_twice_fails_without_writing_profile`; `test_review_round3.py::test_F5b_failed_output_write_rolls_the_store_back`. File modes / umask: no dedicated test. |
| **Terminal / artifact injection** from scraped titles or answers | All untrusted text is escaped for Rich markup and stripped of ANSI/control characters before printing; log lines strip control characters; `report.md` escapes Markdown/HTML in model- or web-derived text; interview answers are capped at 2 000 characters. | `security.py::safe_text`, `security.py::sanitize_answer`, `logging_setup.py`, `workflow/export.py::_md` | `test_logging_and_security.py::test_atomic_write_and_terminal_escape` (Rich escaping, control characters, answer cap). Markdown escaping in `report.md`: no dedicated test. |
| **Resource exhaustion** | Timeouts on every network call (Firecrawl `timeout_ms`, `ChatOpenAI(timeout=180, max_retries=0)` via `config.MODEL_REQUEST_TIMEOUT_S`, robots.txt 10 s), per-page character cap (60 000), raw-link cap (500) before DNS (same-site and exclusion checks run first), ≤ 10 URLs per `scrape_pages` call, a fetch-attempt budget (2 × pages) that also counts failures, page/question/scrape-call/discover-call/model-call caps, optional USD budget, retries capped at `MAX_RETRIES` with bounded backoff. Firecrawl's internal retry loop is disabled (`max_retries=0`) and its API URL is pinned. | `config.py`, `agent/middleware.py`, `agent/tools.py`, `web/scraper.py`, `web/discovery.py` | `test_review_round3.py::test_fetch_attempt_budget_and_url_cap` (attempt budget, `TOO_MANY_URLS`), `::test_private_ip_redirect_empty_and_truncated_pages` (page cap), `::test_model_call_cap_exports_partial_with_hint`; `test_review_round2.py::test_partial_run_resumes_with_higher_budget`; `test_scrape_retry.py` (capped retries); `test_exit_resume_interview.py::test_question_limit_is_enforced`. Raw-link cap, model timeout value and Firecrawl pinning: no dedicated test. |
| **SQL injection / data integrity** | Parameterized queries only; JSON columns written with `json.dumps`; WAL mode; schema version recorded; multi-step store mutations run in one transaction. | `state/run_store.py` | `test_review_round3.py::test_transaction_rolls_back_and_nests`, `::test_shift_list_paths_keeps_conflict_records_and_skips_clashes`. Parameterization is by construction (no string-built SQL); no dedicated test. |
| **Supply chain** | `uv.lock` pins every dependency; CI runs `ruff` with the `S` (bandit) rule set as a gate, and `pip-audit` as an **advisory** step (findings are reported as a workflow warning, not a failure); `make audit` behaves the same (`|| true`). | `pyproject.toml`, `.github/workflows/ci.yml`, `Makefile` | — |
| **Polite crawling** | `robots.txt` respected (per-host cache, agent-specific rules honored, ≤ 5 same-site redirects re-validated by the guard, 512 KiB cap, 5xx treated as disallow-all), identifying `User-Agent`, 1.5 s pacing between live fetches, one tool call per step so there are no fetch storms. | `web/robots.py`, `agent/tools.py::scrape_pages`, `agent/middleware.py::SerialToolCallsMiddleware` | `test_security_review.py::test_robots_respects_agent_specific_disallow_and_5xx`, `::test_robots_follows_same_site_redirect_only`; `test_review_round3.py::test_solo_ask_user_guard_rejects_a_bundled_call`. Pacing delay and `parallel_tool_calls=False`: no dedicated test. |

## Review history

An independent security review (2026-10-02) found two high-severity issues that are fixed and
regression-tested in `tests/test_security_review.py`: the redirect re-check used the requested
URL instead of the engine-reported final URL, and Deep Agents' default general-purpose subagent
would have run the tools without this middleware stack. Medium/low findings (evidence not tied to
values, delimiter spoofing, hostile-link crashes, robots.txt handling, traceback locals, unredacted
stored errors, unbounded fetch attempts, multi-tenant domains, file permissions) are fixed as
described above. A third review round (`tests/test_review_round3.py`) added the per-item
grounding rule, the atomic finalize transaction, fail-fast handling of OpenAI authentication /
permission / bad-request / not-found errors, and the fetch-attempt, URL-count and private-IP
redirect regression tests.
