# Security notes

This tool fetches arbitrary public web pages, feeds them to an LLM, and writes files. The
controls below are implemented in code and covered by tests (`tests/test_url_guard.py`,
`tests/test_logging_and_security.py`, `tests/test_happy_path.py`).

| Threat | Control | Where |
|---|---|---|
| **SSRF** via the start URL, discovered links, or redirects | `http(s)` only; no embedded credentials; default ports only; URL length cap; the hostname is resolved and **every** A/AAAA answer must be publicly routable (no loopback, RFC1918, link-local incl. cloud metadata `169.254.169.254`, CGNAT `100.64/10`, multicast, reserved, unspecified, IPv6 `::1`/`fc00::/7`/`fe80::/10`, IPv4-mapped, 6to4/Teredo). Numeric hosts in decimal/hex/octal forms are rejected. Malformed or hostile URLs raise `URLGuardError` (never a crash). The **final URL after redirects** (Firecrawl's engine-reported `metadata.url`) is re-checked and must stay on the same registrable domain with no https→http downgrade; well-known multi-tenant hosts (`*.github.io`, `*.vercel.app`, …) are treated as separate sites and IP hosts compare exactly. `robots.txt` is fetched through the same guard with a timeout. | `web/url_guard.py`, `agent/tools.py::process_page`, `web/robots.py` |
| **Prompt injection** from scraped content | The agent has no action tools beyond the run's own SQLite store (read-only virtual filesystem, no shell). Deep Agents' default general-purpose subagent and `task` tool are disabled, so every tool call passes through our middleware stack; the builder fails fast if `task`/`execute` ever appear. Web-derived tool output is wrapped in "untrusted content" delimiters by middleware and any `<<<`/`>>>` inside page text is neutralized so the region cannot be closed early; the system prompt states page text is data. Instruction-like phrases are detected and logged as `INJECTION_SUSPECTED` without being acted on. | `agent/builder.py::disable_default_subagent`, `agent/middleware.py::UntrustedContentMiddleware`, `security.py::detect_injection`, `agent/prompts.py` |
| **Fabricated facts, URLs or quotations** | Every website evidence row must name a page fetched in this run, quote a verbatim (whitespace/markdown-normalized) substring of its cached text of 25-1200 characters, and share at least one content word with the field value it supports; otherwise it is rejected and the model is told why. Interview evidence must reference an answered question that covered that field, and the value must reflect the answer. When a value changes, the evidence attached to that path (and its children) is marked stale. Field paths are validated against the contract allowlist and values are re-validated with Pydantic after every update. Unresolved conflicts are omitted from the export. Ungrounded fields are reported in `report.md` and `evidence.json`. | `agent/tools.py::_verify_website_evidence`, `schema.py::parse_field_path`, `agent/tools.py::finalize` |
| **Secret leakage** | Keys are `SecretStr` loaded from env/`.env` only (never CLI args). A redaction filter masks the loaded keys and `sk-…`/`fc-…`/`lsv2_…`/`Bearer …` patterns in every log record, including exception text; the same redactor runs on warnings stored in the run database and on error text printed to the console. Typer tracebacks never show local variables. `.env` is git-ignored; `doctor`/`status` show presence only. | `config.py`, `logging_setup.py::RedactSecretsFilter`, `logging_setup.py::redact_text`, `cli.py` |
| **Path traversal** via `--run-id` / `--runs-dir` | Run ids must match `^pb-\d{8}-[a-z0-9]{6}$`; every artifact path is resolved and asserted to stay inside the runs directory; cache file names are SHA-1 of the URL. | `security.py::validate_run_id`, `security.py::safe_child` |
| **Half-written outputs / permissions** | `company_brain.json`, `evidence.json`, `report.md` are validated first and written atomically (temp file + `os.replace`). The CLI sets `umask 077`; run directories are `0700`; databases, logs, caches, `evidence.json` and `report.md` are `0600` (they contain interview answers); only `company_brain.json` is `0644`. A fatal run never writes a profile. | `security.py::atomic_write_text`, `workflow/export.py`, `cli.py` |
| **Terminal / artifact injection** from scraped titles or answers | All untrusted text is escaped for Rich markup and stripped of ANSI/control characters before printing; log lines strip control characters; `report.md` escapes Markdown/HTML in model- or web-derived text; interview answers are capped at 2 000 characters. | `security.py::safe_text`, `security.py::sanitize_answer`, `logging_setup.py`, `workflow/export.py::_md` |
| **Resource exhaustion** | Timeouts on every network call (`Firecrawl timeout`, `ChatOpenAI(timeout=60, max_retries=0)`), per-page character cap, raw-link cap before DNS (same-site and exclusion checks run first), ≤10 URLs per scrape call, a fetch-attempt budget (2 × pages) that also counts failures, page/question/scrape-call/discover-call/model-call caps, optional USD budget, retries capped at `MAX_RETRIES` with bounded backoff. Firecrawl's internal retry loop is disabled and its API URL is pinned. | `config.py`, `agent/middleware.py`, `agent/tools.py`, `web/scraper.py`, `web/discovery.py` |
| **SQL injection / data integrity** | Parameterized queries only; JSON columns written with `json.dumps`; WAL mode; schema version recorded. | `state/run_store.py` |
| **Supply chain** | `uv.lock` pins every dependency; CI runs `pip-audit` and `ruff` with the `S` (bandit) rule set. | `pyproject.toml`, `.github/workflows/ci.yml` |
| **Polite crawling** | `robots.txt` respected (per-host cache, agent-specific rules honored, ≤5 same-site redirects re-validated by the guard, 512 KiB cap, 5xx treated as disallow-all), identifying `User-Agent`, 1.5 s pacing between live fetches, one tool call per step so there are no fetch storms. | `web/robots.py`, `agent/tools.py::scrape_pages`, `agent/middleware.py::SerialToolCallsMiddleware` |

## Review history

An independent security review (2026-10-02) found two high-severity issues that are fixed and
regression-tested in `tests/test_security_review.py`: the redirect re-check used the requested
URL instead of the engine-reported final URL, and Deep Agents' default general-purpose subagent
would have run the tools without this middleware stack. Medium/low findings (evidence not tied to
values, delimiter spoofing, hostile-link crashes, robots.txt handling, traceback locals, unredacted
stored errors, unbounded fetch attempts, multi-tenant domains, file permissions) are fixed as
described above.
